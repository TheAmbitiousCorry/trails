# Storage

One SQLite database per project at `~/.trail/<project-id>/trail.db`, opened with WAL mode, a 5-second busy timeout and immediate write transactions, by a pure-Go driver (no C toolchain). Concurrent writers queue on the database lock instead of failing with `SQLITE_BUSY`. The project id is a random slug stored in the repo at `.trail/id`, which is committed; a repo is a `--repo` flag value (the flag repeats), a path registered over HTTP, or a path remembered in `~/.trail/<id>/repo`, and anchors resolve against it. One server process serves many projects, one database each, see [Registry](#registry).

## Tables

- `signs(id, parent_id, title, position)`: the tree's structure is stored; a sign's summary, edges and scent are computed from its children at read time and never stored
- `entries(id, sign_id, kind, title, read_when, body_json, body_schema, tags_json, tier, tier_before_stale, promoted_by, superseded_by, distinct_reason, decided_by, decided_at, created_at, updated_at)`; `superseded_by` is a denormalised copy of the `supersedes` link for cheap filtering
- `entry_aliases(entry_id, read_when)` for queries merged in from a gap and `read_when` lines merged in from a duplicate write
- `anchors(id, entry_id, type, path_or_url, range_start, range_end, hash, fetched_at, last_checked_at, ok, extra)`
- `links(from_id, to_id, relation)` with relation in `requires`, `see_also`, `supersedes`, `conflicts_with`; symmetric relations are stored once and queried both ways
- `versions(id, entry_id, body_json, title, read_when, anchors_json, actor, created_at)`
- `sessions(id, actor, task, task_type, runtime_session_id, blocks, started_at, ended_at, ended_by)`
- `events(id, session_id, at, tool, target, depth, result, shown_json)`
- `gaps(id, sign_id, session_id, query, paths_json, state, resolution, target_id, reason, opened_at, resolved_at)`
- `tags(id, description, defined)`: the tag vocabulary; a tag written before it is defined has `defined = 0` and is absent from orient
- `ids(id, freed_at)`: slugs of deleted entries, so an id is never reused
- `settings(key, value)` for caps and thresholds: `fan_out_cap`, `search_threshold`, `search_min_corpus`, `duplicate_threshold`, `paraphrase_threshold`, `open_gap_cap`, `dismiss_cap`, and an optional `cap_<kind>_words` per kind
- `schema_version(version, applied_at)`; migrations are numbered and forward-only, and every entry carries a `body_schema` integer column naming the content schema its body was validated against

## Search

`entries_fts` is an FTS5 table (porter unicode61) over title, `read_when` plus aliases, and plain-text body, weighted 2, 2, 1, refreshed inside the write transaction by one Go function. There is no trigger: SQL cannot walk the JSON body. Ranking is bm25 multiplied by a tier factor (verified 1.0, provisional 0.8, stale 0.5); dormant and superseded entries are excluded, and entries tagged with the query's `task_type` get a 1.25 boost. A miss is no hit above `search_threshold` on the raw bm25 score. bm25 gives a term no weight once it appears in half the corpus, so below `search_min_corpus` entries (default 20) any FTS match counts as a hit and the threshold is not applied. The duplicate check compares a hit's score against that hit's score for its own title, `read_when` and first paragraph, so `duplicate_threshold` is a fraction of a perfect match (default 0.8) and does not drift with query length. `paraphrase_threshold` (default 0.5) is the share of the body's three-word shingles found in its anchored files.

## Process

One Go binary, `trails`, with four subcommands: `serve` (the default, also what a bare invocation or the flags alone run), `register`, `open` and `status`. `trails register [--repo]` creates `.trail/id` in the repo when it has none, then asks the server at `--addr` to open the project (`POST /api/projects`), and prints its title and id; it exits 1 naming the address when no server answers. `trails open [map|trail|graph]` asks the server at `--addr` (see [Address](#address)) for what to show and opens that page in the browser (`xdg-open` on Linux, `open` on macOS; it prints the URL alone when neither exists or `TRAILS_NO_BROWSER=1`); `trail` opens the most recent session that is still open, else the most recent one, else the session list. `trails status` prints the project title, entry count and open gap count on one line. Both exit 1 with a message naming the address when no server answers. `serve` runs on a local port, see [Address](#address): the Vue build embedded at `/`, the MCP at `/mcp`, a JSON API at `/api` for the front end, read-only but for `POST /api/signs`, and the two hook endpoints under `/api`, see [adapters](./adapters.md). There is no authentication: Trails is a single-user local tool and nothing from any permission system reaches it. The one check is that a request is refused when its Host header is not the listening address, or when it carries an Origin other than `http://<listening address>`, so a web page open in the browser on another site cannot drive the server. The MCP transport is stateless; the session is identified by the `session_id` argument, never by transport state, and the session names its project, see [Registry](#registry). Anchor re-checks run when an agent reads an entry and in each project's sweep, which runs when the project opens and every six hours; the sweep also expires provisional entries and closes idle sessions. There is no second process.

## Registry

The server holds a registry of open projects keyed by project id. Each project owns its store, its repo path, its anchor checker and its sweep. Opening a repo reads `.trail/id` and refuses a repo that has none: the id is created by the CLI, by `serve` for each `--repo` it is given and by `trails register`, and by nothing else; in particular a request over HTTP never writes into a repo. The open then takes `~/.trail/<id>/trail.db`, applies `.trail/map.md` and writes the repo path to `~/.trail/<id>/repo`. On start the server opens every `~/.trail/<id>/` whose `repo` file names a directory that exists and holds `.trail/id` with that id, then each `--repo`; one that cannot open is logged and skipped. `serve` with no `--repo` serves only what it already knows, and a repo joins later through `POST /api/projects {repo}`: the repo must be an absolute path to a directory that holds `.trail/id`, else the request is refused (`400` for a path that is not an absolute directory, `422` `not_opted_in` for a repo with no `.trail/id`, which is left untouched). The reply is `{id, title}` and registering an open project again returns it and moves its repo path as described below. `GET /api/projects` replies `{projects: [{id, title}]}` ordered by id; the title is the root sign's title.

Two checkouts that share an id (a clone, a worktree) are one project. The later open replaces the repo path in memory and in the `repo` file and logs the change, and anchors resolve against that path from then on.

A call that carries a session id is served by the project whose `sessions` table holds the id. The registry remembers each match in memory and looks again after a restart, so a restart loses no open session. A session id that no project holds is refused `unknown_session` and is not logged, because there is no database to log it in. The sweep runs once per project. The hook routes find their project as [adapters](./adapters.md) describes; the browser routes act on the only open project and answer 409 `project_ambiguous` when more than one is open.

## Map file

The project may declare its sign tree and tag vocabulary in `.trail/map.md`, committed beside `.trail/id`. A `# Signs` heading holds bullets nested two spaces per level, and a `# Tags` heading holds `- name: description` bullets; blank lines and other lines are ignored. The server applies the file inside `Open`, after seed, in one transaction on every start, and the MCP never writes it. A listed sign that does not exist is created under its parent at its position among its listed siblings, and an existing one keeps everything it has. An unlisted sign is deleted only when it holds no entries and no child signs; otherwise it is kept and a log line names its id and counts. A listed tag is upserted as defined, and a defined tag left out of the file is set to `defined = 0`, never deleted. With no file nothing changes, and a malformed line stops `Open` with its line number.

## Address

A server address is the `--addr` flag, else `TRAILS_ADDR`, else `127.0.0.1:7777`. `serve`, `register`, `open` and `status` apply the same rule, and the shell hooks apply it to build `TRAILS_URL`, see [adapters](./adapters.md). Nothing is read from a repo: one machine has one address, and one server on it holds every project.

## Content schema

Allowed nodes: paragraph, heading (levels 2 to 4; a heading with no level is refused), bullet and ordered lists with list items, code block, blockquote, image, table with its row, cell and header nodes, hard break, text. A Markdown construct outside this list is refused by name (`unsupported: html block`), never dropped silently. Allowed marks: bold, italic, code, link (http, https, mailto, or a relative href with no scheme). An image src is http, https, or a path starting with `/media/`; no route serves that path. Depth cap 32, byte cap 64 KB. The walker lives in `internal/content` and refuses with a rule named `schema:<rule>` and a fix. It is pinned by the fixtures in `server/internal/content/testdata/`, one accepted document per node and mark and one refused document per rule. The Markdown adapter's `unsupported: <construct>` refusal fires before the walker, on constructs Markdown can express that the schema cannot hold: HTML blocks and inline HTML tags of known elements (an angle-bracket word that names no HTML element, such as `<UTC>`, is prose and is stored as literal text), task lists, strikethrough, headings at level 1 or above 4, thematic breaks, footnotes, ordered lists starting anywhere but 1, link and image titles, inline images, table column alignment, and anything after the language in a code fence. The emitter is canonical and the round-trip guarantee is structural equality through JSON plus byte identity on a second emit, for every body the walker accepts; two adjacent lists of one kind merge on re-parse, marks are re-ordered to link, bold, italic, code, and a table whose first row has no header cells comes back with one. `read` validates a stored body before converting it and returns the `schema:*` refusal when a body fails, which only happens if the store was written around the write path.
