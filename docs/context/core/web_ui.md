# Web UI

The browser is the human's view of the same database the MCP serves. It is a Vue 3 app embedded in the binary and served at `/`; its data comes from `GET` routes under `/api/p/<id>`, one project each; the writes are `POST /api/p/<id>/signs`, which creates a sign as a human actor, and the edit, confirm, supersede, promote and sweep routes below. Every browser write is logged by one helper under session id `user`. A reload on any page works because the server returns the app for `/` and for any path under `/p/` that is not a file.

## Projects

One server holds many projects and each browser page belongs to one. The page paths below are relative to `/p/<id>`, `<id>` being the project id from `.trail/id`. Every data route is `/api/p/<id>/...`, resolved to that project's database before the handler runs; an unknown id is 404, and a data route without the prefix does not exist. A page path with no `/p/<id>` prefix (`/graph`, `/entries/x`) is a link from before the prefix: it redirects (302, query kept) to the same path under the project when the server holds exactly one project, and to `/` when it holds none or several. `GET /api/projects` lists the projects, see [storage](./storage.md#registry).

**Switching.** The sidebar's project drop-down (see Shell) is the only way between projects; there is no project list page. `/` has no page of its own: the browser sends it to the last-used project (kept in `localStorage`) or, with none remembered, the first one listed, and a server holding no project shows a line naming `trails register`.

## Shell

Every project page is a left sidebar beside an article column. The sidebar holds the brand, a native drop-down listing every project from `GET /api/projects` by title with the current one selected (one project still shows it, with one option); choosing another opens that project's Map at `/p/<id>` and the tree reloads for it. Then a search box, the tree and the page links (Map, Graph, Sessions, Gaps, Provisional, Staged, Tags, Rejections). Below 900 px the sidebar is hidden behind a Menu toggle at the top of the page; the toggle stays visible and opens the sidebar as an overlay.

- **Tree.** Every sign with its entries nested, fetched once per project from `/api/p/<id>/graph` and fetched again when the browser moves to another project. Signs are collapsed by default. Opening a sign or entry page opens its ancestors and marks the page as current.
- **Search.** Typing filters the tree to titles containing the text and opens the matching branches. From three characters the box also calls `/api/p/<id>/search` and lists up to eight hits above the tree, each with its tier and sign path, linking to the entry. Escape clears the box.

Tier dots, tier chips, kind labels and the "read when" prefix carry a tooltip, shown on hover and keyboard focus, that names what the mark means; the texts live in `frontend/src/tips.ts`.

## Pages

- **Map** (`/`). The full tree, collapsed to its root's children, each node a disc coloured by the tier mix of its subtree, with its entry count, stale count and open-gap count. Click a twist to expand. A heat toggle sizes each disc by reads in the last 30 days and prints the count. A tag selector re-draws the tree with only the entries carrying that tag, listed under their home signs; a second selector limits the tree to the subtree of one sign, so a tag crossed with a sign shows one matrix cell as a sign tree.
- **Graph** (`/graph`). The whole tree drawn as a map in one of three layouts, switched by three buttons (Ridge, Topo, Cluster) and remembered in the browser. In every layout a sign's child signs come before its entries. Signs are squares and entries are discs coloured by tier and sized by reads in the last 30 days. Ridge and Topo share one step rule: a domain's entries sit one step after it, a sub-sign one step beyond those entries, and its own entries one step beyond that. Ridge runs the tree left to right with the trailhead at the left, one column per step, each column starting past the longest label in the column before it, each sub-sign subtree in its own vertical band. Topo is a road map: the trailhead at the centre, one dotted ring per step, each ring starting past the previous ring's longest title, trails drawn as roads with casing and the roads out of the trailhead widest. A sub-sign's trail curves like its siblings' trails to their column or ring through a phantom point there, then runs straight on to the sub-sign, so no two trails cross. Cluster draws each domain as an island: a circle sized by the area its names need, packed with a margin around the trailhead's own circle so no island covers it, its towns spaced by label width and kept inside the circle, under a soft hull. A sub-sign with its subtree is a peninsula, a padded circle of its own hung off the island's far side with its own hull; the island's towns stay out of it and the island's hull stretches around it. Cluster is seeded and settled before it is drawn, so it is the same on every load. A sign holding more than 12 entries of one kind shows them in Ridge and Topo as one node labelled "<n> <kind> entries", and a click on it opens the sign; Cluster draws every entry. Typed links are drawn only in Cluster, as faint lines; in every layout hovering or focusing a node lights that node's typed links, and in Ridge and Topo they appear only then. The view zooms and pans, a click opens the sign or entry page, and the drawing fits itself to the view without magnifying past full size; a Fit button refits it. A `focus` query trims the map to the subtree of one sign (the sign of an entry, with the entry outlined) and a "Whole map" link clears it; the sign and entry pages link here that way. A `tag` query keeps entries carrying the tag and the signs on their paths. A legend names the marks.
- **Sign page** (`/signs/:id`). The path from the root, the sign's title, its summary as a lede, a link to its local graph, and a row of chips: document count, section count, verified and provisional counts, and stale and open-gap counts when they are not zero. A "Sections" list follows when the sign has child signs, one row per child with a square mark, its title and its summary line. A "Documents" list holds the sign's direct entries, one row each with a tier dot, the title with a muted kind label, and the `read_when` line prefixed "read when"; the whole row links to the entry page. Entry bodies, tags and anchors appear only on the entry page, and edges are not shown. A form at the foot creates a child sign and can move the sign's child signs and direct entries under it; a refusal shows beside the form with its rule and fix.
- **Entry page** (`/entries/:id`). One entry: path, tier, kind, chain length, reads in 30 days, last update, `read_when`, tags, who decided and when, a superseded notice, a link to its local graph, a staged badge naming the branch when the entry is held by one (with the original it will replace, if any), the body, snippets for file and range anchors, each anchor with its last check time and a failed flag, typed links and backlinks, and the versions by author and time. Beside a `conflicts_with` link between a verified entry and a provisional one, the verified entry's page shows a "Supersede with <title of the copy>" button and the provisional copy's page shows "Supersede <title of the original>"; either posts to `/api/p/<id>/entries/{id}/supersede` and the page reloads showing the superseded notice. An entry already superseded, or a link to a dormant entry, shows no button. An Edit button and a Confirm button sit under the badges. Edit opens an in-page form in place of the body, anchors, links and versions: title, `read_when`, the Markdown body in a textarea beside a live preview, tags as comma separated text, anchors as rows in the write tool's shape (a type select with the fields that type takes), `requires` and `see_also` as editable id rows (both are always sent whole), and `decided_by` and `decided_at` for a decision; kind and sign are shown and not editable. Beside Save one sentence says that saving keeps the entry's tier and Confirm is how you vouch for it. Confirm posts to the confirm route and a refusal names the failed anchor. Edit is not shown for a staged entry (a line names its branch) or an entry with a `body_problem`. An entry with staged copies shows a warning before Save naming each branch: the copy comes back as a pair to resolve and does not replace this entry. A refusal shows its rule and fix in a `role=alert` box that takes focus; a duplicate refusal offers replace, or distinct with a reason, and sends the save again with `resolution`. A 409 keeps the draft and shows the newer entry beside it with a button that starts the draft again from the newer text. Every field has a label.
- **Sessions** (`/sessions`). The 200 most recent sessions with task, actor, start, how each ended, and counts of looks, searches, reads, writes, confirms, off-trail reads and misses.
- **Session trail** (`/sessions/:id`). The task at the top, then the session's walk on the same map, in the Ridge, Topo or Cluster layout the Graph page remembers (Ridge until one is chosen). Every hop is walked from the trailhead along the tree path to its target, in the foreground colour in all three layouts, over the same trails the static map draws, so a sub-sign's segment bends through the same phantom point. The segments draw in sequence; at each sign passed the prongs an agent saw there (`forkOf`, rebuilt from the map as it is now) are drawn faint and the prong taken solid, and a numbered badge lands on the target. A hop whose entry is folded into a group in Ridge or Topo lands its badge on the group. The prerequisite entries served with a hop hang off its target as short dashed spurs. A range slider (arrow keys move one hop) and a Play/Pause button, 650 ms per hop, step through the hops; the page opens on the finished walk and Play restarts it from the trailhead. A caption reads "Forks as the map is now", because a fork is not stored as it was served. Beside the map a pane shows the current hop: for an entry its title, `read_when`, first paragraph and a link, for a sign its title and link, for a search the query text. Below the map the route is listed as text, one row per hop, each row a button that selects the hop and each showing the sign, entry or query it named, turn-backs, misses (linked to their gap), refusals and prerequisite chains. With `prefers-reduced-motion` nothing animates and Play jumps to the last hop. An off-trail block lists the native reads the hooks forwarded: the reads turned back to an entry first, each with the entry it pointed at, then, apart from them, the other reads (`checked`, `unmapped`, and the `ok` rows of after-read hooks) with the entry that anchors each path, if any; `GET /api/p/<id>/sessions/<id>` serves each row's `result` so the page can group them, and a second block lists the entries the session wrote or confirmed, which are also highlighted in the route.
- **Gap queue** (`/gaps`). Open gaps with the sign they belong to, the query or paths, the session that opened them and when.
- **Provisional queue** (`/provisional`). Provisional entries, most read first, with all-time and 30-day read counts, the number of sessions that confirmed each, and its sign path.
- **Staged** (`/staged`). Every entry held by a branch (see [entries](./entries.md)), grouped by branch name, each group headed with the base branch and a "branch gone" mark when no ref for the branch remains. A row is laid out like a Provisional card and adds its promotion state (`branch only`: no landing commit pinned; `committed`: landing commit shown; `abandoned`: branch deleted before its work landed, entry dormant), the last anchor check, and, for a stage-over copy, a link to the original it replaces with the note that a verified or changed original is left as a conflicting pair. Each row has a Promote now button, which posts to the promote route; a "Sweep now" button at the top posts to the sweep route and prints what it did in a status line. The browser is not a session on any branch, so the page lists staged entries from every branch, abandoned ones included. A project holding none shows a line saying so.
- **Tags** (`/tags`). Every tag with its description and use count; undefined tags come first and are marked. A tag links to the map filtered by it.
- **Rejections and dismissals** (`/logs`). Refused calls grouped by rule and actor kind with the 50 most recent, and the gaps agents dismissed with their reasons.

## Routes the shell and the graph use

All under `/api/p/<id>`.

- `GET /api/p/<id>/graph` returns `nodes` (every sign with its parent, and every live entry with kind, tier, reads in 30 days, home sign and tags) and `edges` (`home` from a sign to each child sign and entry, and the typed links as stored). `tag` keeps entries carrying the tag and the signs on their paths to the root. `focus` with `depth` 1 or 2 keeps the nodes within that many edges of the focus; an unknown focus is 404 and a depth outside 1 to 2 is 400. `session` adds the session row and `route`: its hops in order, each with tool, target, kind (sign, entry or query), result, miss, turn-back and the prerequisite entry ids served with it; an unknown session is 404. Without `session`, `route` is null.
- `GET /api/p/<id>/search?q=` runs the agents' search with no task type and a limit of ten, returning the hits with their sign paths and `miss`. An empty `q` is 400.
- `POST /api/p/<id>/signs` takes `parent_id`, `title` and `move` (child sign ids and entry ids to move under the new sign) and creates a sign with the `write_sign` rules; a refusal is 400 with its rule and fix, an unknown parent 404.
- `GET /api/p/<id>/entries/{id}` also carries what the edit form needs: `etag` (the entry's `updated_at`, the concurrency token), `form_anchors` (each anchor as the write tool takes it: `type`, `path`, `start`, `end`, `url`, `command`, `sha`), `requires` and `see_also` (id lists; `see_also` counts links written from either end, because a save replaces both lists whole), `decided_by` and `decided_at`, `staged` (the branch hold of this entry) and `staged_copies` (`id` and `branch` of each staged entry that stages over this one). Kind and sign (`sign_id`, `path`) are shown and not editable.
- `POST /api/p/<id>/entries/{id}` saves an edit. The body is JSON with `etag` (required) and the whole form: `title`, `read_when`, `body_markdown`, `tags`, `anchors`, `requires`, `see_also`, `decided_by`, `decided_at`, and `resolution` with `distinct_reason` to answer a duplicate refusal. It calls `entries.Write` as actor `user` with `Edit` and `IfMatch` set to `etag` (see [entries: human edits](entries.md#human-edits)), so the entry keeps its tier and a stale entry stays stale until Confirm. Success returns the same JSON as the GET, with the new `etag`. A refusal is 400 with the body `rule: fix`; a staged entry is 400 `staged_elsewhere` naming the branch; an unknown entry is 404; a missing `etag` is 400. `stale_edit` is 409 with the GET's JSON for the entry as it is now, plus `refusal`. Logged as tool `edit`, with `refused:<rule>` on a refusal.
- `POST /api/p/<id>/entries/{id}/confirm` runs `trail.ConfirmHuman`: the anchors are re-checked and the entry becomes verified. A stale anchor is 400 `stale: ...` naming it, an unknown entry 404. Success returns the GET's JSON. Logged as tool `confirm`.
- `POST /api/p/<id>/entries/{id}/supersede` takes `by`, the id of the copy, and retires entry `{id}` in favour of it; the two must be linked by `conflicts_with`, else 400, and an unknown entry on either side is 404. The browser logs it under session id `user` as tool `supersede`.
- `GET /api/p/<id>/staged` returns `branches`, each with `branch`, `base`, `alive` (a local or remote-tracking ref for the branch exists) and `entries`: id, title, kind, tier, `state` (`branch_only`, `committed` or `abandoned`), `landing` (the pinned commit or empty), `last_check` (newest anchor check) and `stages_over` (id, title and tier of the original, or null). `GET /api/p/<id>/entries/{id}` carries `staged` (branch, base, landing, stages_over), null for a normal entry.
- `POST /api/p/<id>/entries/{id}/promote` promotes a staged entry by hand through the code the sweep uses, whatever its branch has done, and logs it under session id `user` as tool `promote`. A promoted copy replaces its original only when the original is not verified and unchanged since staging; otherwise the pair is linked `conflicts_with` and resolved on the entry page. An abandoned entry returns to provisional. The entry's anchors are then checked like any normal entry's, so work that has not landed reads stale. A normal entry is 400 (`refused:not_staged`), an unknown one 404. The reply names the original it replaced, if any.
- `POST /api/p/<id>/sweep` runs one sweep now and returns its counts (`checked`, `dormant`, `deleted`, `closed`, `promoted`, `abandoned`, `base_unresolved`).
