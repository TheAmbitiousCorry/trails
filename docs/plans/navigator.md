# Navigator: an agent that keeps the map current

Runs after [staged-docs](./staged-docs.md) is complete; it uses that plan's base Viewer and contract 4, and bumps the contract to 5.

## Goal

An agent can ask Trails what the map does not cover, close that distance under the normal write rules, and leave its work confirmed rather than expiring. A read-only MCP tool `coverage` returns the work list ranked by evidence of need; `resolve_gap` lets any session fill or merge an open gap under a relevance check; the `trails:navigate` skill works the list in bounded passes and hands each pass to two verify sessions it starts itself. Success is measured on confirmed output, not on entries written. Governing sections: [mcp: tools](../context/core/mcp.md), [trail: gaps](../context/core/trail.md), [principles](../context/core/principles.md) rules 4, 6, 7 and 10.

## Definitions

- **Live entry:** not dormant, not superseded, visible to the base Viewer (staged-docs).
- **Covered file:** a tracked file is covered when a live entry has a file or range anchor on it, or a dir anchor on an ancestor directory whose subtree holds at most `coverage_dir_max` (setting, default 50) tracked files. One predicate, `anchor.Covers`, used by `coverage` and by the pre-read hook's `unmapped` decision, which today defines it twice (`mcp/api.go:322`, `:361`). The dir ceiling stops one `src/` anchor from marking a whole tree covered.
- **Excluded file:** a lockfile (fixed list: `go.sum`, `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `Cargo.lock`, `composer.lock`, `poetry.lock`), a path with `linguist-generated` or `linguist-vendored` set (`git check-attr`), or a binary file (`git ls-files --eol`, index side `-text`).
- **Unmapped items:** walk directories from the checkout root. For a directory `D`, let `F` be its non-excluded tracked files below and `U` the uncovered ones. If `F > 0` and `U == F`, `D` is one item and the walk stops there. Otherwise recurse into each child directory, and if `D` has uncovered files directly in it, those form one item with path `D` and `loose: true`, naming up to five. Each item reports `files` (`F` of that item) and `unmapped` (`U`). `commits_90d` is the number of distinct commits in the last 90 days (`coverage_window_days`, default 90) touching any file of the item, from one `git log --since --name-only` per call. Ranked by `commits_90d`, then `unmapped`. Worked example: `a/x.go` covered, `a/y.go` uncovered, `b/p.go` and `b/q/r.go` uncovered, `go.sum`, `README.md` uncovered at the root. Items: `b` (files 2, unmapped 2), `a` loose (y.go; files 1, unmapped 1), `.` loose (README.md; files 1, unmapped 1). No path is a prefix of another item's except a loose item and the directories below it, which the `loose` flag distinguishes.

## Decisions

- **`coverage(session_id, within?, limit?)`** returns four lists, each item naming the sign to write under (the deepest sign whose entries anchor the nearest covered ancestor, else the root): `gaps` (open, every session: id, query, sign, age), `stale` (id, title, sign path, failed anchors), `off_trail` (unanchored paths read natively in `coverage_window_days`, with count), `unmapped` (as defined). `limit` defaults to `coverage_limit` (10), max 25; all four numbers are settings (principles rule 5). Rejected: surfacing the work as a virtual sign under `look`, because `unmapped` needs git and `look` is promised cheap.
- **Order of work, in the skill:** gaps, stale, off-trail, unmapped. A pass does not aim for full coverage.
- **The why.** For each item the navigator reads `git log` for the files it anchors. A decision is written only when a commit message states a reason, with `decided_by` the commit author and `decided_at` the commit date; otherwise it writes a summary or procedure. It never invents a reason (principles rule 10).
- **Stale entries.** A stale entry is corrected in place with `write(entry_id, ...)`, which lands provisional even when the entry was verified before it went stale: its anchors failed, so the old verification was of a claim that no longer holds, and the version history keeps it.
- **Verify handoff is part of the pass.** After its writes and its `session_end`, the navigator (running as a coordinator) starts two verify workers, each its own Trails session, on the entries the pass wrote or corrected, following `trails:verify`. A worker that corrects an entry counts it as a navigator miss. A pass reports `written`, `verified`, `corrected`, `left provisional`. **Target: at least 80% of a pass's entries verified when the pass ends.** A pass below target says so first in its report.
- **Shared gaps, gated.** `fill` and `merge` accept another session's open gap when the gap's query covers at least `search_threshold` of its content terms in the target entry's title, `read_when` and body (the search coverage rule, applied to one entry), else refused `gap_mismatch`. `gaps` gains `resolved_by`. A session may close at most `gap_close_cap` (setting, 10) gaps it did not open. `dismiss` stays owner-only. The roadmap item is edited to say it shipped in this form and why its stated trigger was waived: the navigator is the next session by construction.
- **Orient.** Gains `stale_count` and `open_gaps` (SQL counts). The `notice` string joins its messages with "; ": the existing gap-cap message first, then "N stale, M open gaps: the trails:navigate skill works through them" when either count is non-zero.
- **Triggers.** The skill's description fires on "update the wiki/map/trail", "document this repo in Trails", "map what's missing", "navigate", and on the orient notice. `skills/trails/SKILL.md` gains one line: when the orient notice names the navigator, finish the task, then tell the user. Recurring passes are the user's `/loop` or `/schedule`, shown in the skill and the README. No claim that a merge triggers anything.

## Non-goals

- Bulk write or dry-run tools; auto-confirming; a navigator tier.
- Skills for runtimes other than Claude Code (they get the protocol line only).
- Editing `.trail/map.md`.
- The pre-read hook's behaviour, beyond calling the shared `Covers`.

## Unknowns

- **Cost** of `coverage` on Caravan (4,824 files) and navvy: budget 500 ms. If over, cache the unmapped list per (checkout, HEAD sha) in memory.
- **Description budget.** The golden caps descriptions at 6,000 characters; current use is estimated near 3,800. `coverage`'s description must fit; measured in step 1.
- **Verify workers as distinct sessions.** Subagents carry composite runtime ids and call `session_start` themselves; check in step 3 that their confirms count as distinct sessions from the navigator and each other.
